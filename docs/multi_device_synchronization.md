# Multi-Device Playback Synchronization

Phase 6 extends the receiver timing foundation into a deterministic simulation of multiple independent playback endpoints. It does not access physical audio devices and does not claim sample-accurate or production-grade distributed clock synchronization.

## Architecture

```text
Reference timeline
        |
        v
Synchronization controller
        |
  bounded correction
        |
  +-----+-----+
  v           v
Endpoint A  Endpoint B ... Endpoint C
  |           |             |
clock       clock         clock
  |           |             |
jitter      jitter        jitter
buffer      buffer        buffer
  |           |             |
playback    playback      playback
```

Each `PlaybackEndpoint` owns its endpoint configuration, impairment schedule, jitter buffer, jitter estimator, clock estimator, simulated playback sink, correction state, and metrics. The endpoints process the same logical stream independently. They are not three labels around one shared timing value.

## Reference and Endpoint Clocks

The reference timeline is the simulation's intended remote timeline. Each endpoint has a ground-truth local model:

```text
endpoint_error(t) = initial_offset + drift_ppm / 1,000,000 * t + correction
```

The local clock is not overwritten or forced to equal the reference. Initial offsets and drift remain endpoint configuration and are measured against the reference. Each endpoint also feeds its received timestamps and local arrival model into the existing `ClockEstimator`, keeping estimated clock state separate from ground truth.

The reported drift convention is positive when the endpoint local clock advances faster than the reference clock. Offset and timing error are reported in milliseconds; drift is reported in ppm.

## Synchronization Controller

At each configured update interval, the controller measures each endpoint's current error and applies a bounded proportional correction:

```text
requested_correction = -error * convergence_rate
applied_correction = clamp(requested_correction,
                           -maximum_correction,
                           +maximum_correction)
```

Corrections are gradual and limited per update. An endpoint is `synchronized` when its remaining absolute error is within tolerance, `synchronizing` while converging, `degraded` when it is far outside tolerance, and `stopped` after shutdown. The controller records the first convergence time and maximum absolute correction.

This is a deliberately understandable educational controller. It does not implement a PLL, PTP, NTP, adaptive latency, or cross-device sample-rate adjustment.

## Interaction With Existing Timing Components

Network arrival events are generated by the existing deterministic impairment utility. Each endpoint inserts its own arrivals into its own bounded `JitterBuffer`, which handles reordering, duplicates, late frames, packet loss deadlines, and concealment. `PlaybackScheduler` remains available for mapping remote timestamps to local play times; the Phase 6 controller adjusts endpoint timing error separately from that scheduling decision.

Packet loss does not directly alter the controller's clock model. Missing frames are concealed by the jitter buffer and counted by the endpoint, so concealment remains an audio continuity policy rather than a synchronization measurement.

## Metrics and Demonstration

The endpoint metrics include configured initial offset and drift, estimated offset and drift, current error, cumulative and maximum correction, synchronization state, convergence time, received/played frames, missing and concealed frames, duplicates, and late packets. The controller reports maximum inter-device skew at a reference time.

The deterministic demonstration uses three endpoints: a reference endpoint, a positive-offset/positive-drift endpoint, and a negative-offset/negative-drift endpoint. One endpoint also receives reordered, duplicated, and lost packets. The simulation runs long enough for drift to accumulate, then repeatedly applies bounded corrections and prints actual convergence measurements.

## Limitations and Future Work

The current model has no physical playback callback, no shared hardware clock, no audio-rate resampling, no adaptive playout delay, and no network control messages. Its endpoint clock model is deterministic and its controller operates on simulated timing error. Production multi-device synchronization would need a carefully designed clock discipline, timestamp transport and filtering, callback-safe queues, resampling or hardware clock coordination, and stronger failure handling. Those concerns remain future work beyond this phase.
